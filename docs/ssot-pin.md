# SSoT pin（正本 → 消費サイトの伝播を強制する）

doc が実行手順そのものになるプラグインでは、consumer が別の doc なので**正本を直しても
伝播漏れが見えにくい**（code-review v2.63.0 のセルフレビューで検出した欠陥 11 件中 6 件が
この型だった）。

CLAUDE.md には規範だけを置き、記法と運用の詳細はここに集約する。
設計判断（なぜマーカー同期でなく pin か）: `.claude/adr/20260813223000-ssot-pin-over-marker-sync.md`。

## 何を強制するか

**内容の一致ではなく、「正本が変わったら消費サイトを確認して pin を打ち直す」手順**を強制する。
言い換え・要約で複製されている関係は一致比較にできないので、ハッシュのずれを
「確認しろ」の合図として使う。

> `routing-axes` の同期は「**同一テキストであること自体が仕様**」の関係を扱う別の仕組み。
> 両者は併存する（あちらは dedent 比較、こちらはハッシュ突合）。

## 記法

消費サイトの**冒頭**に置く:

```
<!-- SSOT: <repo ルート相対の md パス>#<見出し前方一致 anchor> @<hash8> -->
```

`validate_plugin_quality.py` の `check_ssot_pins` が正本の該当節をハッシュして突合し、
ずれていれば Critical。

## 打ち直し

```bash
python3 .claude-plugin/scripts/validate_plugin_quality.py --update-ssot-pins
```

**明示操作**。pre-commit では自動更新しない（自動化すると確認の強制力が消える）。
**repo 全体の pin を一括で打ち直す**ので、**全消費サイトを確認してから**使う。

## 落とし穴

- **新規 pin は hash を手計算しない**。`@00000000` のダミーで宣言し `--update-ssot-pins` で
  確定させる（初期値も検証も同じ切り出しを通るので、これが正規経路）
- **hash は 8 桁の小文字 hex**。外すと `pin 記法が不正で検証されない` の Critical になる
  （黙って無効化はしない）
- **pin 宣言はファイル冒頭＝最初の見出しより前**に置く。pin した節の中に pin があると
  打ち直しが収束せず、これも Critical
- **doc に記法例を書くときはフェンスか行内コードに入れる**（生きた pin として拾われない）
- **正本・消費サイトとも md のみ対応**。スクリプトを正本にはできず、非 md に pin を書いても
  警告なく無効化される
- **節の区切りは見出しレベルで決まる**ので `#8` は同レベルの `## 8.5` を含まない（別 pin を打つ）。
  anchor `8` は `## 8.5` に吸着せず、一致が 2 件以上なら曖昧として Critical
