## 2. 入れたもの

### 2.1 #170 — エイリアスは「最新世代」ではなく「親の世代」に解決される（`255e144`）

規約が「エイリアスは最新世代に自動解決される」と保証していたが偽。`opus` を指定した sub は**親（実行時に選択したメインモデル）の世代を継ぐ**。Claude Code v2.1.241 のモデル解決関数（family step-down / テレメトリ名が `family_alias_stepped_down` / `parent_inherit`）と 2 セッションの実測で確認した。

**踏み下げは直すべき挙動ではなく、使うべき制御点**として扱うことにした。実行時にコスト都合でメインモデルを下げれば判断層もそれに従う＝**セッション単位でパイプライン全体の重さを選べる**。「具体 ID をピン留めしない」規約は維持し、理由を「追随不要」→「**ピン留めすると実行時の選択を無視する**」に付け替えた。

副産物として `CLAUDE_CODE_SUBAGENT_MODEL` の存在と優先順位（`env` → tool の `model:` → frontmatter → 親継承）を記録した。**全 sub に一律でロール別ルーティングを潰すので既定では使わない。**

### 2.2 #169 — payload にモデル世代（`adb909b`）

`models: {schema, main, main_distinct, sub_distinct}`。transcript の `message.model` からの機械計測で、**呼び出し側が渡しても捨てる**。retro / backfill の層別キーに追加。

**`main` は単一世代の回にだけ入る。** 混在と引き当て失敗はどちらも `null` で `mixed` バケツへ落とす。片方を代表値に選ぶと交絡サンプルが単一世代の分布に混ざり、#156 の「深さのコストが下がった」と「4.8 だから軽い」が永久に分離できなくなる。

**母集団に 2 種以上あるときだけ層別キーに足す。** 1 種の期間まで割ると既存の `effort/size_tier` バケツが n=1 に砕ける。

### 2.3 #167 — 軸の寄せ漏れを検出（`fa3fd0a`）

対応表は `orchestration-measurement.md ## 16` の深い位置にあったが、**payload を組み立てるのは両 SKILL の Step 6 でそこには無かった**。実運用で `intended` 2 件が `base_derived` に寄らず `unknown` に落ちていた。

- 対応表を payload を組み立てる場所に置いた
- `measurement_gaps` に `axis-unknown` / `demoted-unknown`。**合計の突合では寄せ漏れを検出できない**（語彙内の値を `unknown` に落としても合計は一致する）
- **publish 側で寄せることは構造的に不可能**だった。payload に届く時点で既にバケツ化済みで、生の `axis` は残っていない

### 2.4 #166 — wave-split の初サンプルが偽陽性（`32d928f`）

期待式に `(meta_reviewer.fired かつ findings_added が 1 以上 ? 1 : 0)` を追加。meta 由来指摘の反証バッチは **meta の出力が存在しない時点では発行できない**構造的な直列で、`meta_reviewer` は `agents` に計上しない契約なので既存の式のどの項にも現れていなかった。

**判定そのものは緩めていない**（既知の reviewer 分割型は meta と無関係）ことを回帰テストで表明した。

### 2.5 #168 — 「報告 0 件」と「価値 0」の分離（`f32d4c3`）

🔁 付録の項目単位マーカー `※ 推奨: <理由>` と `appendix: {listed, recommended}`。retro に「報告 0 件のうち推奨ありの回」と推奨率。

**上限は設けなかった。** 閾値は実測で決める流儀（`## 9` の偽陽性撤去の先例）に従い、かつ上限を先に置くと「惜しい指摘が上限を超えたとき silent に落ちる」ことになって `削ったら痕跡を必ず残す` の系列に反する。膨らみは**推奨率の高止まり**として先に表に出る。

## 3. 3 回とも同じ形の欠陥だった

**検証・規約が、それを必要とする場所まで届いていない。**

| 回 | 正本 | 届いていなかった場所 | 捕まえたもの |
|---|---|---|---|
| #167 | `## 16` の軸対応表 | payload を組み立てる SKILL Step 6 | 人手（実データの突合） |
| #168 | publish の `appendix` 検証 | それを読む `review-retro.sh`（`--logs` で他マシンのログも合算する） | **変異テスト** |
| #169 | 「transcript は `message.model` を持つ」 | テスト fixture（持っていなかった） | **実データ 160 transcript の走査** |

3 つとも「正本は正しいが、消費する側に届いていない」。**SSoT pin はこの型を狙って作られた仕組みだが、対象が md 同士に限られる**（Gotchas / ADR-20260813223000）ので、#168 の「スクリプト → スクリプト」も #169 の「実データ → fixture」も pin では宣言できない。

今回はそれぞれ変異テストと実データ走査が拾ったが、**どちらも「たまたま回した」**。規約還流の候補としては、

- **fixture が実データの形と一致しているかを確かめる手順**（#163 の「未知データの構造を確かめる」の裏返し。書き**込む**側にも同じ確認が要る）
- **検証を足したら「読む側にも同じ検証が要るか」を確かめる手順**（#168 の型）

の 2 つが立つ。ただし**まだ 30 日 3 回の閾値には達していない**（`failure-journal` の集計対象）。`/retro` で candidates と合わせて見るのは次回でよい。

## 4. 実データを先に見て潰した欠陥が 2 件

どちらも #163 が規約化しようとしている手順（**未知データの構造を確かめる**）をそのまま踏んだ結果。

1. **`<synthetic>`**: `message.model` の値を 160 transcript で走査したら、モデル ID ではないプレースホルダが 11 件あった。素通しすると**単一世代の回まで `main_distinct` が 2 件になり mixed に落ちる** — 実装前に走査していなければ、混在検出が偽陽性で埋まっていた
2. **`main` の混在**: 25 セッションを走査して混在 2 件・4.8 親 2 件を実際に観測した。「混在は理論上ありうる」ではなく**実在する経路**として `mixed` バケツを設計できた

**この 2 件は「実装 → テスト → 実データで確認」の順だったら見つからなかった。** 実データが先だったから設計に入った。

## 5. 途中で方針を変えた点

- **ユーザーの前提を単価だけで否定しかけた**（記録済み / candidates）。「Opus 5 → 4.8 でコストが下がる」に対し「単価が同じだから意味が薄い」と結論したが、**単価が同じなら差は消費トークン量に全部乗る**ので、むしろ効く可能性が高い側だった。支配的な因子（消費量）を認識しながら副次的な因子（単価）で結論を出した
- **#168 の定義を総括ではなく項目単位に置いた**。issue の提案は「総括の番号付きリスト」だったが、散文は数え方がぶれる。項目マーカーなら `※ 推奨:` の行数で一意になり、理由を 1 件ずつ書かせること自体が歯止めになる
- **CHANGELOG の「回帰テスト 16 件」が実際は 19 件**だった（本レポート作成時に実測して発覚・修正済み）。**記録された数字の正確さがこのセッションの主題そのもの**なので直した
- **その訂正で書いた本レポートの「188 → 228」も誤りだった**（正しくは 194 → 234）。セルフレビューの doc-substance reviewer が実測で検出。原因は数え方で、`set()` を使ったため**クラスを跨いだ同名テスト 5 件**が重複除去されていた（同一クラス内の重複は無く、テストは隠れていない）。**同じ型を同一セッションで 2 回**踏んだので、以後この種の件数は数え方を併記する

## 6. テストを書く人向けのメモ

- **meta 発火は `declared` に +1 される。** `meta_reviewer` は `agents` に計上しない契約だが `agents-mismatch` の突合式は `fired` を別途足す。fixture の体数を揃えないと `agents-mismatch` が立ち、**wave 判定そのものが抑止されて** `wave-split` が出ない（実装中に 2 件落ちた）
- **fixture は実データの形に揃える。** `message.model` を落としたままだと publish が毎回 `models` 欠測になり、**欠測が既定の形としてテストに焼き付く**
- **`bump-version.sh --sync` は CHANGELOG の `## [x.y.z]` 見出しを正とする。** 見出しに `vNEXT` は使えない（本文の `vNEXT` は bump が解決する側）。SSoT pin の打ち直しは bump の後

## 7. セッション末に arm B を 1 回走らせた（#171 の決着）

前回・今回とレポートの持ち越し筆頭に居続けた `reviewer_effort_profile=differentiated` を、v2.88.1 の差分に対するセルフレビューとして 1 回実行した。

### 結果: 不採用で決着し、9 ファイルのスカフォールドを撤去した（v2.89.0）

| 群 | 体数 | subagent tokens 中央値 | 実行時間 中央値 |
|---|---:|---:|---:|
| `high`（bug-detection / claude-md-compliance） | 2 | 201,532 | 9.7 分 |
| `medium`（test-quality / doc-substance / comment-accuracy） | 3 | 197,907 | 10.4 分 |

**差が出なかった。** recall は測っていない（BLOCKER / CRITICAL が 0 件で指標が存在せず、反証レイヤーも `no-eligible-findings` で未実施）が、**コスト差が無い以上 recall がどちらでも結論は不採用**になるので決着させた。

### 走らせたこと自体の収穫の方が大きかった

- `models`（#169）/ `appendix`（#168）の**初の実サンプル**が取れた
- **`waves` の変数上書きによる恒常的な偽陽性を検出した**（v2.84.0 混入 / v2.88.2 修正）。explorer wave 数の変数が dispatch ブロックの総 wave 数に上書きされ、**layered な全レビューで「一括発行が破られた」が鳴っていた**。本物の打点漏れ警告も到達不能だった
- 自分の直近 5 コミットに対する指摘 7 件 + 付録 13 件（うち 4 件に `※ 推奨:` を付けた ＝ #168 の初適用）

**「ボトルネックは計測不足ではなく、指定済みの A/B が走っていないこと」という 2026-08-23 の診断が裏付けられた。**

### §3 のパターンを、レポートを書いた直後に自分で 2 回踏んだ

- **reviewer の指摘（confidence 95・実データ再現つき）を適用したら回帰テスト 3 件が落ちた。** `GEN_SPLIT` から `unrecorded` を外すと #169 が防ごうとしたプーリングが起きる。差し戻した。**この回は反証レイヤーが未実施**で、独立検証を通っていない指摘をそのまま適用していた。止めたのは回帰テスト
- **変数リネームで参照サイトを 1 つ取りこぼし**、publish が `NameError` で落ちて 21 件が赤になった。手元の再現は短絡していて見えなかった

どちらも §3 の「正本は正しいが、消費する側に届いていない」と同じ型。**§3 はもう「気づいたこと」ではなく、繰り返し実証されたパターンとして扱ってよい。**

### この回で分かった運用上の注意

- **`high` 帯では反証レイヤーが MAJOR に掛からない**（対象は BLOCKER 60-94 / CRITICAL 80-94）。MAJOR しか出ない回では、レポートの全指摘が**独立検証を一度も通っていない**。修正を適用する前にそれを前提として扱うこと
- **`measure-tokens.sh` の per-agent 内訳は要らなかった**（持ち越し #4）。Agent tool の戻り値が体ごとの `subagent_tokens` / `duration_ms` を返すので、1 run 内の対照にはそれで足りる
