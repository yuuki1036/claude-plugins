# AI-DLC v2 とこの repo の比較評価（2026-11-07〜08）

AI-DLC v2（[awslabs/aidlc-workflows](https://github.com/awslabs/aidlc-workflows)）と比べて、この repo のやり方を
作り直すべきかを評価した記録。結論と判断の理由は ADR-20261108182901（`.claude/adr/20261108182901-adopt-aidlc-v2-principles-incrementally.md`）に置き、
本書はその根拠の数値と、評価から出た issue の対応を持つ。

## 結論

根本からは作り直さない。AI-DLC v2 の思想（人の判断を少しずつ機械の検査へ移し、移せた分だけ人の出番を減らす）は採る。
実装は仕様の原則 7（一度に全部を入れ替えず、いま書ける事後条件から始めて足していく）に従い、原則を 1 つずつ既存の
プラグインへ当てはめる。エンジン化・プラグインの統合・プラグイン間依存の解禁はしない。

## 方法の違い

両者は「散文の指示が守られなかったら、決定的な仕組みへ移す」という原理を共有している。違うのは当てる先。

- AI-DLC: 工程の正しさ（次の stage・承認の記録・完了の判定）を決定的なエンジンが持ち、LLM は 1 手ずつ実行する。
  前提はチーム（mob 3〜5 人）・無人実行・承認の捏造の防止。エンジンの `core/tools` は 235,589 行、hooks は 17,104 行、
  CHANGELOG の見出しは 284（評価のときに AI-DLC の repo で数えた値）
- この repo: 工程の順序は SKILL.md の散文が持ち、スクリプトにしているのは局所（構成決定・オラクル・照合など）だけ。
  両者の違いはここが最も大きい

### AI-DLC 自身の既定

- 11 の scope のうち 10 で `guard_policy: off` が既定（off は 4 つの fence をすべて下げる）
- Stop hook も、人がいる承認つきの実行では止めない
- 強制が効くのは、チームがロックした設定か無人実行のとき、つまり人の判断がすでに下されているときだけ。
  1 人が対話で使うこの repo の使い方では、重い仕組みのほとんどが既定で外れる

- `_requirements` の任意のプラグイン連携 21 件（2026-11-08 に数えた）が、強制インストールに変わる

## 取り込む原則と issue

| 原則（AI-DLC の信条・規則） | 当てはめる issue |
|---|---|
| LLM に数えさせない・照合させない。1 つの規則に持ち主は 1 つ | #425 scope_size の閾値と判定を 1 つのスクリプトにまとめる |
| エージェントへの指示をその段の中身に絞る | #426 feature-dev と self-review の本文を phase ごとに分ける |
| 段と段の成果物をファイルで受け渡す | #427 explorer の結果を architect に渡す |
| 人の修正を事後条件・guardrail の候補にする（Learn の区画） | #430 人の修正・差し戻しを拾い続ける経路 |
| 規則の束を subagent にも届ける（条件付き） | #428 SubagentStart で事実主張の規約を届ける |
| レビューの記録を作業ツリーに結び付けて照合する（条件付き） | #429 receipt 照合を記録だけで 1 週間回す |

#428 と #429 は実験で、着手条件を観測で判定する形にしてある。#429 の照合は、m1 の transcript で `git commit` を含む
Bash 呼び出し 1,343 回のうち 1,123 回（83.6%）が同じコマンドで stage もしていた（2026-11-08 に数えた）。
PreToolUse の時点の index を見て照合すると、ほとんどの commit で誤って鳴る。

評価の途中で見つかった欠陥は、#422（maintain 系が確かめずに完了 Issue を削除する）・#423（他プラグインの有効判定が
キーの有無だけを見る）・#424（knowledge index を上限なしに注入する）に起票した。

## 取り込まないもの

- エンジンによる全面化（工程の順序・遷移・承認の記録をエンジンが持つ形）
- プラグインの統合と、プラグイン間依存の解禁
- 134 種の監査イベント、Guard Policy、11 プロファイルと composer
- HUMAN_TURN（hook の入力では、人の発話と他のセッションからのメッセージを区別できない）
- Stop での強制続行
- mob 型の agent 構成
- learnings ritual（Claude Code の auto memory が同じ役をしている）
- 出典タグの sensor（典拠の検査は 5 述語すべてで真陽性 0 だった。ADR-20260817120000 で却下済み）、traceability

## 物差しの見直しと、その後の計測

上の数値は「AI-DLC の仕組みを入れたら、こちらの失敗をどれだけ防げるか」で測ったもの。AI-DLC v2 の目的は失敗を
防ぐことではなく、人の判断を機械へ移して介入を減らすことなので、この物差しは思想に対する反論にはならない。
そこで人の介入点を数える計測を別に作り、2 台で回した（手順と結果は
`docs/session-reports/2026-11-08-human-intervention-measurement.md`、候補は #418・#419・#420）。
エンジン化をしない判断は、どちらの物差しでも変わらない。原則 7 が一度に全部を入れ替える導入を否定しているため。

## 前提

この結論は、利用者が 1 人で、対話で使う前提に立っている。チームで使う・無人で回す・承認の正当性を監査する必要が
出る、のどれかに当たったら、ADR を supersede して判断し直す。
