# worktree-setup

git worktree ベースの並列開発環境をセットアップする。worktree 名から DB 名と port を動的に導出し、メインの clone および他 worktree との衝突を防ぐ。

## 適用範囲

- Claude Code を **同時に複数並列** で走らせるプロジェクト
- 同一 DB / port を共有すると壊れる構成（DB レコード競合、`EADDRINUSE` 等）
- すでに `git worktree add` で worktree は作ってあるが、env / DB / port の切り分けが手付かずの場面

main の clone 上ではこの skill は実行不可（メイン環境を壊す可能性がある）。`git worktree add` でまず worktree を作ってから、その worktree 内で本 skill を起動する。

## 実行手順

### Step 1: 3 状態判定

worktree の現在状態を 3 値で判定する。

| 状態 | 条件 | アクション |
|---|---|---|
| `main` | `GIT_DIR == GIT_COMMON_DIR` | **エラー終了**。worktree skill は main では実行不可 |
| `worktree-ready` | worktree かつ env マーカーファイルが存在 | `--force` 指示がなければスキップして現状報告 |
| `worktree-unconfigured` | worktree かつ env マーカーファイルが無い | セットアップ実行（Step 2 以降） |

詳細フロー図は [references/state-matrix.md](references/state-matrix.md) を参照。

#### 検出疑似コード

```bash
detect_worktree_state() {
  local git_dir
  local git_common
  git_dir=$(git rev-parse --git-dir)
  git_common=$(git rev-parse --git-common-dir)
  local marker="envs/.backend.env.worktree"

  if [[ "$git_dir" == "$git_common" ]]; then
    echo "main"; return
  fi
  if [[ -f "$marker" ]]; then
    echo "worktree-ready"; return
  fi
  echo "worktree-unconfigured"
}
```

判定結果別の挙動:

- `main`: メッセージを出して即終了。`git worktree add ../<name> <branch>` でまず worktree を作るよう案内
- `worktree-ready`: マーカー / env / port / DB 名を表示してスキップ。`--force` 指定時のみ再生成
- `worktree-unconfigured`: Step 2 へ進む

### Step 2: worktree 名と base 情報の取得

```bash
WORKTREE_DIR=$(git rev-parse --show-toplevel)
WORKTREE_NAME=$(basename "$WORKTREE_DIR")
BRANCH=$(git rev-parse --abbrev-ref HEAD)
```

`WORKTREE_NAME` を以後の DB 名 / port 計算の seed として使う。プロジェクトによっては `BRANCH` 由来の slug を使いたい場合もあるので、命名規約は [references/db-naming.md](references/db-naming.md) を参照してプロジェクト固有に override する。

### Step 3: DB 名の割当

ベース DB 名に worktree 名をサフィックスとして付与する。

```bash
BASE_DB="${BASE_DB:-appdb}"  # プロジェクト固有。env or .env から読む
DB_NAME="${BASE_DB}_${WORKTREE_NAME}"
```

DB 名規約・既存 DB との重複チェック・create 方法のサンプルは [references/db-naming.md](references/db-naming.md) を参照。MySQL / PostgreSQL / SQLite で create コマンドが違うので、プロジェクトで使っている DB に合わせて override する。

### Step 4: port の動的割当

メインで使っている port を起点に +10 単位で空きを探索する。

```bash
allocate_port() {
  local base=$1  # 例: 3000 / 8000
  local candidate=$base
  while [ "$candidate" -lt $((base + 1000)) ]; do
    if ! lsof -i ":$candidate" -t >/dev/null 2>&1; then
      echo "$candidate"; return
    fi
    candidate=$((candidate + 10))
  done
  echo "ERROR: no free port" >&2
  return 1
}

BACKEND_PORT=$(allocate_port 8000)
FRONTEND_PORT=$(allocate_port 3000)
DB_PORT=$(allocate_port 5432)
```

空き判定の詳細（`lsof` / `nc -z` の使い分け、競合 worktree との race）は [references/port-allocation.md](references/port-allocation.md) を参照。

### Step 5: env ファイル書き出し

worktree 用の env ファイルを `envs/` 配下に書く。実 env ファイル（`.env.local` 等）は触らず、worktree 用の上書きファイルとして配置する。

```bash
mkdir -p envs

cat > envs/.backend.env.worktree <<EOF
# Auto-generated by worktree-setup. Do not commit.
DB_NAME=${DB_NAME}
DB_PORT=${DB_PORT}
BACKEND_PORT=${BACKEND_PORT}
WORKTREE_NAME=${WORKTREE_NAME}
EOF

cat > envs/.frontend.env.worktree <<EOF
FRONTEND_PORT=${FRONTEND_PORT}
BACKEND_URL=http://localhost:${BACKEND_PORT}
WORKTREE_NAME=${WORKTREE_NAME}
EOF
```

env テンプレ全文と読み込み側（`source envs/.backend.env.worktree` を `package.json` scripts や docker-compose に組み込む方法）は [references/env-templates.md](references/env-templates.md) を参照。

### Step 6: マーカーファイル確認

Step 5 で書いた `envs/.backend.env.worktree` がそのまま **マーカー** を兼ねる。次回以降の `detect_worktree_state` が `worktree-ready` を返す根拠になる。

`envs/` ディレクトリは `.gitignore` に含める（プロジェクト固有の値を含むため）。プロジェクト直下の `.gitignore` に未追加なら、ユーザーに追記を案内する。

```bash
if ! grep -q '^envs/' .gitignore 2>/dev/null; then
  echo "envs/" >> .gitignore
fi
```

### Step 7: DB セットアップ

DB を実際に作成する。既存 DB と衝突しないかチェックしてから create。

```bash
# 例: PostgreSQL
psql -U postgres -c "CREATE DATABASE ${DB_NAME};" 2>&1 || true

# 例: マイグレーション実行（プロジェクトで使っているコマンドに合わせる）
# pnpm db:migrate
# bundle exec rails db:create db:migrate
```

DB セットアップは副作用が大きいため、ユーザーに「DB を作成・マイグレーション実行してよいか」を確認してから実行する。

### Step 8: 完了レポート

ユーザーに以下を提示して終了:

- worktree path / branch / worktree 名
- 割当てた DB 名 / port (backend / frontend / db)
- 書き出した env ファイル一覧
- 起動コマンド例（env を読み込んだ状態で dev server を起動する手順）

## override 方法

DB 名規約・port 割当ロジック・env テンプレ・マーカーファイル位置は **プロジェクト固有** なので、references の内容をそのまま流用せず、プロジェクトに合わせて書き換える前提。

- `envs/.backend.env.worktree` のキー名はプロジェクトの env 規約に合わせる
- `BASE_DB` / port base はプロジェクトの `.env.example` から読む
- DB 名の命名規約（snake_case / kebab-case / 文字数制限）は DB エンジン依存

各 references の末尾にも「プロジェクト固有のため必要に応じて override してください」と明記してある。

## 絶対厳守ルール

- `main`（メインの clone）では実行しない。`detect_worktree_state` が `main` を返したら即終了
- 既存 DB を drop しない。create のみで、既存があったらスキップ
- 実 env ファイル（`.env` / `.env.local`）を上書きしない。worktree 用の `envs/*.worktree` に書く
- `.gitignore` に `envs/` を追加するなど、worktree 固有ファイルがコミット対象にならないよう配慮する
- port 衝突時は黙って占有せず、空きが無ければエラー終了してユーザーに報告
