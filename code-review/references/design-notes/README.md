# design-notes（実行時には読まない）

**レビュー実行中に読むファイルは 1 つも無い。** ここにあるのは「なぜその規範になっているか」— 実測値・失敗の履歴・却下した代替案・判断待ちの観測ログ。規範（何をせよ）は `references/` 直下のガイド本体にあり、実行にはそちらだけで足りる。

読むのは **ガイド本体を編集するとき**。規範をゆるめる／変える前に、その規範が何を防いでいたのかをここで確認する。

| ファイル | 対応するガイド |
|---|---|
| `orchestration-rationale.md` | `orchestration-guide.md` 系（並列発行 / HEAD SHA / ファイル経由渡し / effort 設計 / 観点カバレッジ検算） |
| `triage-rationale.md` | `triage-guide.md` 系（規模キャップの実測 / wave 可視化 / 縮小のロールバック条件と監視 / 未解決の観測） |
| `scoring-rationale.md` | `scoring-guide.md`（2 軸の必要性 / `severity-inflated` の穴 / パネル運用の将来拡張） |
| `pr-context-format.md` | `scripts/fetch-pr-context.sh` の出力フォーマット |

## なぜ分けたか

ガイド本体は毎レビューでメインコンテキストに読み込まれる。根拠の散文は **Opus 5 が規範に従うためには不要**（規則があれば従える）だが、**将来の編集者が規範を壊さないためには必要**。読者が違うので、ファイルを分けて読み込みタイミングも分けた。

**根拠を消したわけではない。** 規範を変更する PR では、対応する design-note の更新も同時に行う。ガイド本体から `design-notes/*.md` への参照が切れていないかは、その PR のレビュー観点に含める。
