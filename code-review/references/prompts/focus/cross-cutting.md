### cross-cutting（クロスカッティング影響分析）
```
## 観点: クロスカッティング影響分析

分析観点:
- 共通モジュール変更による影響範囲
- 暗黙の依存関係（イベント、グローバル状態、環境変数）の変更
- モジュール境界の違反（レイヤー間の不適切なアクセス）
- 循環依存の導入
- 副作用の波及（import 時の副作用、モジュール初期化順序）
- **共有モジュールのコメント・名前が特定の利用側に寄っていないか**（GitHub issue #273）: 複数の利用側から import されるモジュールで追加・変更したコメント（と識別子名）が、**提供側の事実**（その値が何で、どこから来て、何を保証するか）で書かれているか。特定の利用側の画面・用途を理由にしている（「〇〇画面で使うため」「△△の表示用」）と、共有モジュールが利用側に依存しているように読まれ、依存の設計を誤読させる。提供側の事実で言い直す案を添える。利用側が 1 つしか無いと git grep で確かめられたものは対象外（共有モジュールでない）

層の役割に照らした置き場所・判断の持ち場・層をまたぐ重複は layer-responsibility の担当（ここでは import・参照の追跡で見える境界違反を扱う）。

影響を受ける可能性のあるモジュール/ファイルを具体的に列挙する。
git grep や Grep で import/参照を追跡して裏付けを取る。
各指摘に影響範囲（ファイル数の推定）を付与。

**severity 目安**:
- BLOCKER: 共通モジュール変更で複数機能が壊れる、循環依存導入で起動不能
- CRITICAL: 暗黙の依存（イベント・グローバル状態）が広く波及
- MAJOR: モジュール境界違反、副作用波及（限定的）
- MINOR: 設計改善提案 / 共有モジュールのコメント・名前が利用側の都合で書かれている（実行時の挙動は変えない）
```
