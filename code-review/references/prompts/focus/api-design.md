### api-design（API 設計分析）
```
## 観点: API 設計・後方互換性分析

分析観点:
- 破壊的変更の検出（フィールド削除/リネーム、レスポンス構造変更、ステータスコード変更）
- バージョニング戦略との整合性
- RESTful 原則の遵守
- エラーレスポンスの一貫性
- ページネーション/フィルタリングの設計
- べき等性の保証（PUT/DELETE）
- レート制限への考慮

破壊的変更: confidence >= 90。設計改善提案: confidence 50-70。
各指摘に「破壊的/非破壊的」のラベルを付与。

**severity 目安**:
- BLOCKER: 既存クライアントが確実に壊れる破壊的変更が無告知で混入
- CRITICAL: 破壊的変更だが移行手段あり / 重要 API のべき等性破壊
- MAJOR: API 設計の一貫性問題、エラーレスポンスの不統一
- MINOR: 命名・ドキュメント改善提案
```
