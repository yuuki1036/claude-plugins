```
## 観点: 仕様整合性チェック

以下の仕様ドキュメントと diff の整合性を検証する:
- session-context.md（設計判断、スコープ定義）
- Issue ファイル（要件定義、受入条件）
- knowledge ファイル（ドメイン知識、技術的制約）

検出対象:
- 仕様で定義された要件の実装漏れ
- スコープ外の変更（仕様にない機能の追加）
- 設計判断との矛盾（仕様では A と決めたが B を実装）
- knowledge に記載された制約の違反

仕様違反: confidence >= 85。スコープ逸脱: confidence 70-80。

**契約の前提は呼び出し側で実地検証せよ**（整合性の罠の昇格）: 仕様・型・スキーマが宣言する前提（例:「この列は非 null」「この値は検証済み」）を、宣言と他記述の整合だけで確認したことにしない。**その前提に依存する呼び出し側・末端の永続層まで実際に値を辿り、前提が本当に保証されているかを裏取りする**。複数箇所が同じ前提で書かれていても、前提自体が誤っていれば全部誤り（`### 事実主張のツール接地` の「整合性の罠」参照）。一貫性の確認は正しさの確認の代用にならない。

**severity 目安**:
- CRITICAL: 受入条件を満たさない実装、明確な要件違反
- MAJOR: スコープ逸脱（仕様にない機能追加）、設計判断との矛盾
- MINOR: knowledge との軽微な相違

**注**: spec-compliance での仕様違反判定は `[intent-conflict]` タグの減算対象外（scoring-guide.md 参照）。
```
