## セッションコンテキストの扱い（reviewer 向け）

**これは reviewer が読む指示である**（オーケストレーターが本文をプロンプトへ展開するテンプレートではない）。分割前は後者だったが、パス渡しに切り替えたことで読み手が変わったので書き換えてある。

プロンプトに `.claude/session-context.md` のパスが渡されている場合、**最初に Read すること**。そこには現在の作業 Issue から抽出された設計判断とコンテキストが書かれている。

読んだうえで以下を適用する:

- **意図的な設計判断と一致する指摘は confidence を大幅に下げる（−30 以上）**。session-context に「この方式を選んだ」「このトレードオフを取る」と書かれている事柄を、その旨に触れずに指摘しない
- **スコープ外と明記された事柄への指摘には `[scope:out]` タグを付ける**（Step 6 でオーケストレーターが severity を 1 段階下げる）
- session-context の記述と diff が**矛盾している**場合は下げない。仕様違反の可能性があるので `spec-compliance` の観点として通常どおり報告する

パスが渡されていない場合は本ファイルの内容は適用外（session-context を持たないプロジェクト、またはブランチ不一致で無効と判定された場合）。
