# ADR-20261103153228: PR 必須にした後も、変異テストは PR の CI では回さず nightly だけで回す

## ステータス

accepted（2026-11-03）

## コンテキスト / 背景

- ADR-20261025123627 は「このリポジトリは main に直接コミットする。スモークが落ちても変更はもう main に入っているので、止める効果は無く、早く知らせる効果だけがある」を前提の一つにして、変異テストを push の CI から外し nightly だけにした
- 2026-11-03 に、利用者の指示でこのリポジトリを PR 必須にした（GitHub のルールセット「main: PR 必須」が main への直接 push・force push・削除を拒否する。マージは利用者が行う / CLAUDE.md の「ブランチ運用」）。PR の CI はマージの前に走るので、スモークが落ちれば着地を止められるようになり、旧 ADR の前提が崩れた
- 旧 ADR のもう一方の根拠は変わっていない。直近 40 回の CI（2026-10-11〜25）でスモークは平均 518 秒・最大 2622 秒かかり、生存を検出したのは 0 回だった。それより前の約 200 回では 4 回。2026-10-24 の push はスモークを通ったまま、nightly が同じ範囲で生存 15 件を出した（GitHub issue #317）
- 作業側は PR の CI を確認するまで完了にしない決まり（CLAUDE.md の「ブランチ運用」と Gotchas）なので、CI の所要はそのまま PR ごとの待ち時間になる
- 前提が崩れたことは、PR 必須化のセルフレビュー（2026-11-03）で doc-substance の指摘として見つかった。利用者が修正を選び、決定を維持したまま前提を書き直す supersede を承認した

## 決定

- PR 必須にした後も、PR / push の CI（`validate.yml`）では変異テストを回さない。変異テストは nightly（`mutation-nightly.yml`）だけで回し、生存・持ち越しは今までどおり nightly が GitHub Issue に起票する
- nightly の範囲・予算・起票の仕方は変えない
- 手元で変異テストを回す条件（新しい lint / 検証ロジックを足したとき・軽量フローと feature-dev が利用者の承認を得たとき）も変えない
- 再判断の条件: nightly の生存が PR 由来で繰り返し出て、マージ前に止めていれば防げたと言える回が見えたら、PR の CI へのスモーク復帰をこの ADR の supersede として判断し直す

## 影響 (Consequences)

- **良い影響**: PR ごとの CI の待ち時間は、旧 ADR の時点と同じく平均 518 秒（最大 2622 秒）少ないまま保たれる
- **悪い影響**: PR 必須で得られた「生存をマージ前に止める」機会を使わない。生存はマージ後、翌朝の nightly の issue で見つかる
- **トレードオフ**: マージ前に止められる効果（実績 40 回で検出 0 回のスモークなので、止める回はほぼ無い見込み）と、PR ごとに払う待ち時間（平均 518 秒）を天秤にかけた。旧 ADR と違い、止める効果がゼロではなくなった点だけが変わった

## 適用方法 (Enforcement)

- 機械強制はしない。`validate.yml` に変異テストの step が無いこと自体が適用で、戻すときはこの ADR を supersede する
- 生存の検出は nightly の起票（`mutation-nightly-report.py`）が担い、GitHub Issue として開いたまま残るので、見落としても消えない
- 再判断の条件（PR 由来の生存の繰り返し）を機械で数える仕組みは置かない。nightly の issue に対象の head と範囲が載るので、起票が続いたときに人が PR と突き合わせれば足りる

## 検討した代替案

- **旧 ADR の決定（push / PR で回さない）をそのまま残し、前提だけが古いまま置いておく**: 後から PR の CI にスモークを戻すかを判断する人が、もう無い前提で天秤を読むことになるので採らなかった
- **PR の CI にスモーク（`--max 5 --strict --related-first`）を戻し、落ちたらマージを止める**: マージ前に止める効果は得られるが、実績 40 回で検出 0 回のスモークに PR ごとに平均 518 秒を払う構図は旧 ADR の時点と同じで、大きな変更の生存はスモークでは拾えていなかった（#317）。今回の前提の変化だけでは採る理由にならない
- **PR の CI で、ルールセットの必須ステータスチェックとして変異テストを要求する**: 上の案に加えてマージ自体を機械的に止めるが、待ち時間の問題は同じで、さらに nightly と二重に回すことになる
