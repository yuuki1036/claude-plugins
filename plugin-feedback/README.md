# plugin-feedback

プラグインへの改善要望・バグ報告を GitHub Issue として作成するプラグイン。

## 使い方

### コマンドで明示的に起動

```
/feedback dev-workflow コミットメッセージの粒度を調整したい
/feedback
```

### 会話中に自然に起動

会話中にプラグインへの不満や要望を言えば、AI が検知して Issue 作成を提案します。

## 公開前の匿名化

起票先（`yuuki1036/claude-plugins`）は公開リポジトリで、投稿した本文は編集しても履歴やアーカイブに残ります。そのため起票・コメントの前に次を必ず行います。

- 業務のリポジトリ名・PR・Issue ID・端末名・コードの識別子・ローカルパスを置き換え表で汎用名にする（`skills/feedback-issue/references/anonymize.md`）
- 起票したセッションの cwd が公開リポジトリでない（業務リポジトリなど）ときは、置き換えた後の本文を Claude が走査し、業務の語が残っていないことをプレビューに示す。判断に迷う語だけを利用者に確かめ、投稿の承認は全文を見せて取る
- 添付ファイルは、業務の画面が写っていないとユーザーが答えたときだけ付ける
- 本文は一時ファイルに書いてから `--body-file` で渡す（送信前に本文を検査する hook が読めるように）

## 前提条件

- `gh` CLI がインストール済みであること
- `gh auth login` で GitHub 認証済みであること

## 構成

| 種別 | 名前 | 説明 |
|------|------|------|
| コマンド | `/feedback` | 明示的に Issue を作成（手順は skill と共通。同じ内容の Issue があれば、そこへのコメントも選べる） |
| スキル | `feedback-issue` | 会話中の要望を検知して Issue 作成を提案 |
