# 公開前の匿名化

起票先の `yuuki1036/claude-plugins` は公開リポジトリで、Issue とコメントは誰でも読める。本文を後から編集しても旧版は編集履歴に残り、公開イベント（Events API）とそれを取り込む第三者のアーカイブにも投稿時点の本文が入る。**投稿した時点で取り消せない**ものとして扱い、プレビューを出す前にタイトル・本文・コメント・添付ファイル名へ下の表を当てる。

## 置き換え表

| 種類 | 見分け方 | 置き換え後 |
|---|---|---|
| 業務リポジトリ名・製品名・社名・チーム名 | 公開されていないリポジトリの名前。会話・cwd・パスに出てきた組織名・製品名 | 「業務リポジトリ A」「業務リポジトリ B」…（同じ Issue の中では同じものに同じ記号）。製品名・社名・チーム名は書かない |
| 業務の PR・Issue の番号と URL | `<業務リポジトリ> PR #123`、`https://github.com/<業務の org>/...` | 「業務 PR」（複数なら「業務 PR A」「業務 PR B」） |
| Issue トラッカーの ID（Linear など）とそれを含むブランチ名 | `ABC-123` 型の ID、`feature/abc-123-...` | `TEAM-123`（別チームなら `TEAMB-1`）。ブランチ名は `feat/TEAM-123` |
| 端末名 | `hostname` の値、シリアル番号風の英数字、ユーザー名入りのマシン名 | マシンの label（`~/.config/claude-review/machine-label` の値。例 `m1` / `m2`）。label が無ければ「別マシン」 |
| 業務コードの識別子 | 関数・コンポーネント・変数・テーブル・API の名前、ドメイン用語 | 役割だけを表す汎用名（`saveA()`、`SearchInput`、`canDoX`、「ある数値フィールド」） |
| 業務のローカルパス | 業務リポジトリの置き場所を含む絶対パス、transcript のディレクトリ名（`-Users-<name>-<repo>` 型） | `~/<work>/...`。パス中のリポジトリ名も上の記号にする |
| 業務ドメインの説明・社内文書の引用 | 何を扱う製品か、業務リポジトリの規約・README・AGENTS.md の文面 | 書かない。要るなら「業務リポジトリの規約で〜と決まっている」と要旨だけにする |

- 公開リポジトリ（claude-plugins 自身など）の Issue 番号・ファイルパスは置き換えない
- スクリプト・ツールの出力を貼るときは、貼る行ごとに表を当てる。パス・ホスト名・PR 番号はこの経路で混ざる
- 業務由来か迷った識別子は置き換える。「名前が汎用的に見える」は残す理由にならない
- 固有名を消すと問題が伝わらないときは、その部分を書かずにユーザーへ相談する

## 完了基準

- タイトル・本文の全行と、添付・コメントの全文を表の全行に照らし終えた
- プレビューの本文の外に「置き換えた種類と件数」（例: 業務リポジトリ名 2 件 / Issue ID 1 件）を添えた。置き換え前の語はプレビューにも本文ファイルにも書かない
